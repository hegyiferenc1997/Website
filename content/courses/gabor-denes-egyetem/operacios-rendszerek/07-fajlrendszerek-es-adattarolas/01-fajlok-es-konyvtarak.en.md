## What you will learn

- what a **file** is, what **attributes** it has and what the extension is for,
- how the **directory tree** is built and what an **absolute** and a **relative** path are,
- what you find in the main Linux folders (**FHS**), and what a **hard** and a **symbolic link** are.

## The file

A **file** is a **named** sequence of data on storage, managed by the OS. The programmer does not need to know which disk blocks it is in – that is the file system's job.

Important **attributes** (metadata):

| Attribute       | Example                                 |
| --------------- | --------------------------------------- |
| name            | `notes.txt`                             |
| size            | 2,345 bytes                             |
| type            | text, image, executable                 |
| owner           | `anna`                                  |
| permissions     | who may read, write, execute it         |
| timestamps      | creation, last modification, access     |

```bash
stat notes.txt       # all metadata of the file
file /bin/ls         # what type it is (based on its contents)
```

The **extension** (`.txt`, `.jpg`, `.exe`) matters on Windows: it tells which program should open the file. On Linux it is only a convention – executability is decided by the **permission**, not the name.

## The directory tree

A **directory** (folder) is also a special file that stores names and references. Directories form a **tree**:

```text
/                      ← root
├── home/
│   └── anna/          ← your home folder (~)
│       ├── lab/
│       │   └── a.txt
│       └── notes.txt
├── etc/
└── usr/
```

- **Absolute path**: starts from the root – `/home/anna/lab/a.txt` (on Windows `C:\Users\anna\lab\a.txt`).
- **Relative path**: starts from the current folder. If you are in `/home/anna`: `lab/a.txt`.
- Special names: `.` = this folder, `..` = the parent folder, `~` = your home folder.

On Linux there is a **single tree**; every drive goes into one of its branches (**mounting**). On Windows every drive has its **own letter** and tree (`C:`, `D:`). The separator is `/` on Linux and `\` on Windows; on Linux upper and lower case **differ** (`A.txt` ≠ `a.txt`).

## The Linux directory layout (FHS)

| Folder       | What is in it?                                             |
| ------------ | ---------------------------------------------------------- |
| `/bin`, `/usr/bin` | user programs (`ls`, `cp`, `python3`)                |
| `/etc`       | system-wide **configuration files** (text)                 |
| `/home`      | the users' home folders                                    |
| `/root`      | the administrator's (root's) home folder                   |
| `/var`       | variable data: **logs** (`/var/log`), caches               |
| `/tmp`       | temporary files (may be deleted at reboot)                 |
| `/dev`       | **device files** (`/dev/sda` = the first disk)             |
| `/proc`, `/sys` | "virtual" files generated by the kernel on the fly      |
| `/boot`      | the kernel and the boot loader's files                     |

According to the UNIX philosophy **"everything is a file"**: the disk, the terminal, even data of running processes are accessible as files.

## Links

- **Hard link** (`ln a.txt b.txt`): a **second name** of the same file. Both names are equal; the file is only deleted when its last name is deleted too.
- **Symbolic link** (`ln -s /etc/hosts hosts`): a small file that contains a **path** – like a Windows shortcut. If you delete the original, the link "dangles".

## Summary

- A file is a named sequence of data with metadata (size, owner, permissions, timestamps).
- Absolute path from the root, relative from the current folder; `.`, `..`, `~`.
- Linux has one tree (FHS: `/etc`, `/home`, `/var`, `/dev` …), Windows has drive letters.
- Hard link = another name for the same file; symbolic link = a reference containing a path.
