## What you will learn

- what a **loadable kernel module** is and how to manage it (`lsmod`, `modinfo`, `modprobe`),
- how to read the **kernel's messages** (`dmesg`, `journalctl -k`),
- what **/proc** and **/sys** show and how a **kernel version** is built.

## Loadable kernel modules

The Linux kernel is monolithic, but it does not have to contain every driver at once. A **kernel module** (`.ko` file) is a piece of code that can be loaded into the kernel **at run time** and removed again – without a reboot. Most drivers, file systems and network protocols are modules.

```bash
lsmod | head                      # loaded modules (name, size, used by)
modinfo vboxguest                 # data of a module (VirtualBox guest additions)
sudo modprobe -r pcspkr           # remove a module (the PC speaker)
sudo modprobe pcspkr              # and load it back, with its dependencies
ls /lib/modules/$(uname -r)/kernel/drivers | head   # where installed modules live
```

Note: a loaded module runs in **kernel mode** with full rights – that is why `sudo` is needed, and why the kernel checks module **signatures** under Secure Boot. (That is why Ubuntu sometimes asks you to enroll the key of the VirtualBox or NVIDIA driver – _MOK enrollment_.)

## The kernel's messages

The kernel writes into its own log: which hardware it found, which driver was loaded, which error occurred.

```bash
sudo dmesg | head -20             # the start of boot: CPU, memory, devices
sudo dmesg -w                     # live watch – plug in a (virtual) USB device!
journalctl -k -b                  # kernel messages since the current boot
```

If the kernel hits a **fatal error**, it stops with a **kernel panic** (the Windows equivalent is the **blue screen**, BSOD, with an error code).

## /proc and /sys

These are **not real** files on disk: the kernel generates their contents on the fly when you read them – a window into the kernel.

| Path                          | What does it show?                               |
| ----------------------------- | ------------------------------------------------ |
| `/proc/cpuinfo`               | data of the processor(s)                         |
| `/proc/meminfo`               | the detailed state of memory                     |
| `/proc/<PID>/`                | data of a process (status, maps, fd …)           |
| `/proc/version`               | the kernel version and build data                |
| `/proc/sys/`                  | **tunable** kernel parameters (`sysctl`)         |
| `/sys/class/net/`             | network interfaces                               |
| `/sys/block/`                 | block devices (disks)                            |

```bash
cat /proc/version
cat /proc/sys/vm/swappiness          # how eagerly the kernel swaps out (0–200, default: 60)
sysctl net.ipv4.ip_forward           # the same with the sysctl command
```

## Kernel versions

```bash
uname -r       # e.g. 7.0.0-15-generic
```

The number means **major.minor.patch**, followed by the distribution's own label (Ubuntu: package revision and flavour, e.g. `generic`). The Linux kernel releases a new minor version roughly every **9–10 weeks**; each year one kernel is designated **LTS** and fixed for years. Ubuntu 26.04 LTS is based on the 7.0 kernel and receives security fixes for it; `sudo apt upgrade` updates it too (a reboot is needed for the new kernel to run).

On Windows the kernel version is shown by `winver` or PowerShell `[System.Environment]::OSVersion`; the kernel file is `C:\Windows\System32\ntoskrnl.exe`.

## Summary

- A kernel module is kernel code loadable and removable at run time (`lsmod`, `modinfo`, `modprobe`); it runs in kernel mode and must be signed under Secure Boot.
- The kernel's log: `dmesg`, `journalctl -k`; fatal error: kernel panic (Windows: BSOD).
- `/proc` and `/sys` are virtual file systems generated by the kernel on the fly; `/proc/sys` parameters are tunable.
- `uname -r`: major.minor.patch + distribution label.
